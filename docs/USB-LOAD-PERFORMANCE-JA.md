# rekordbox USBの初回読み込み速度の調査

調査日: 2026-10-15

## 現在の動作（0056）

初回のカタログ作成はPDBのメタデータだけを読み、一覧を先に表示します。
プレイリストや曲一覧が開かれたら、その一覧の曲のANLZをバックグラウンドで順番に読み込みます。
表示中の行の波形要求を優先し、準備できた行から更新するため、曲のロード操作は不要です。
解析情報はUSB接続セッション内で再利用し、デコードした波形は上限付きキャッシュに保持します。
画面外の曲は解析情報を先読みし、実際の波形デコードは表示時に行います。

一覧切り替えでは待機中の読み込みを破棄し、実行中の最大1曲だけ完了を待ちます。
古い一覧や取り外したUSBの結果は表示しません。波形がない曲や壊れた解析ファイルがあっても
後続の曲の読み込みは続行します。所有者確認・改変検出・読み取り専用の扱いは維持しています。

対応パッチ: [0056](../patches/0056-browser-background-waveform-previews.patch)。
Linux aarch64で、追加3件を含むモデルの7件と関連テスト全体を確認しました。
全体では361件成功・38件skipです。通信制限で失敗した更新確認の5件は、
ローカル通信を許可した再実行で成功しました。Linux本体と起動フォルダを更新済みです。
Windows向け契約チェックは成功しましたが、今回のWindows本体のビルドは未実施です。
以下の0049の説明・測定結果は、当時の動作の記録です。

## 対応状況（0049）

下記は0048までの実装に対する調査記録です。報告された規模は約1000曲、待ち時間は数分以上でした。
0049で、初回カタログ作成から全曲のANLZ読み取りを外し、曲のロード時にその曲だけを解析する
方式へ変更しました。曲名・アーティスト・プレイリストはPDBから先に公開します。
ブラウザの行描画やスクロールだけでは解析を開始せず、未ロード曲の小さな波形プレビューは空欄になります。
ロード後の解析結果は接続セッション内で再利用します。
キュー・グリッド・波形の所有者確認、USBの交換・改変検出、保存時の検証は維持します。

対応パッチ: [0049](../patches/0049-rekordbox-load-analysis-on-track-demand.patch)。
実際のWindows PCと対象USBでの短縮時間は未計測です。

確認結果: 開発PCのLinux x86_64で、1000曲の合成データによる一覧・プレイリスト・
行選択後のGUI更新が解析を開始しないことと、1曲のロードでその曲だけ解析されることを確認しました。
同時要求、キャッシュ、評価情報の保持、所有者の不一致、同サイズ・同mtimeの解析ファイル改変、
PDB交換、未ロード曲への保存拒否もテストしました。
最新の選択テストは365件中327件成功・38件skip・失敗0件です。
PC用Linuxの本体・起動フォルダまで更新しました。今回のWindows実行ファイルの生成は未実施です。

## 報告された症状と結論

Windows版1.5で、USBを挿してブラウザを開くと「USB Loading...」の表示で待ち、
その間は操作を受け付けない。読み込みが一度終われば、その後はスムーズに動くという報告です。

**最も有力な要因は、全曲の解析ファイルの読み取り・検証を完了するまで、
ブラウズを開始できない構造です。** この構造は1.5と現在のryumu版の両方にあります。
今回の0045はLinuxのUSB検出・交換判定の改善であり、この初回読み込み量は削減していません。

ただし、対象Windows PC・USBでの計測と再現は行っていません。
曲数・読み込み時間・USB内のファイル構成も未取得です。
初回待ちを長くする実装は確認できましたが、アプリ全体の入力停止の原因を確定したものではありません。

  公式Mixxx 2.5.6アーカイブから、rekordbox関連とブラウザの該当ソースを
  当時の0001〜0017パッチで再構成し、適用成功を確認しました。
- 1.5.1の記録時点 `d48d1157e3d2841f8e0a5d9035f2d0541fbaab8b` との差分では、

## 初回読み込みで重い箇所

| 優先度 | コードで確認した動作 | 待ち時間への影響 |
| --- | --- | --- |
| 高 | `populate()` が全曲に `applyAnlz()` を実行する | 選択したプレイリストの曲数ではなく、USB全体の曲数に応じて準備量が増える |
| 高 | 各曲のANLZ候補 `.DAT` / `.EXT` / `.2EX` を調べ、存在する候補を読む | 多数のファイルの存在確認・パス解決・オープン・読み取りが発生する |
| 高 | 波形のDescriptorモードでもファイル全体を読みSHA-256を計算する | 波形本体のメモリ保持は遅延するが、初回のファイル読み取りは省略されない |
| 高 | カタログ完成まで `Ready` にならず、`chooseSource()` がブラウズ開始を拒否する | 待っている間、曲やプレイリストを開く操作が進まない |
| 中 | `export.pdb` を探索時とロード時に複数回全体読み取りする | 大きなデータベースでは追加の読み取り・ハッシュ計算になる |
| 中 | 全曲の音声・解析・アートワークのパスを解決し、存在確認する | Windows側のファイルシステム応答時間が曲数分積み重なる可能性がある |

初回処理は概ね次の順です。

1. USBを探索し、`export.pdb` のフィンガープリントを取得する。
2. ワーカースレッドで `RekordboxUsbSession::load()` を開始する。
3. PDBを読み、曲・プレイリストの情報を解析する。
4. 全曲についてパスを解決し、各曲のANLZ候補を読み取り・検証する。
5. PDBと媒体が変わっていないか再確認する。
6. 完成したカタログを公開して `Ready` にする。

この間に曲一覧だけを先に公開する段階はありません。
同じ接続セッションでは完成済みカタログを再利用するため、初回だけ遅いという報告に整合します。
新しいセッションを作る際には、同じ解析処理が再度必要です。

## 「操作できない」の切り分け

`RekordboxFeature::startNextLoad()` は `QtConcurrent::run()` を使っています。
全曲のANLZ読み込み自体がGUIスレッドで直接実行される、という実装ではありません。
一方でブラウザは、USBが準備中なら曲一覧への移動を明示的に拒否します。
これだけでも「押しても先へ進めない」状態になります。

ウィンドウの移動・再描画・演奏画面への切り替えまで止まっていた場合は、別の確認も必要です。
GUIスレッド側には `QStorageInfo::mountedVolumes()` による定期的なボリューム確認や、
SOURCE表示時の `QStorageInfo` による容量取得があります。
これらのOS呼び出しが対象Windows環境で待たされていないかは未計測です。
カタログ完成時のプレイリストツリー生成もGUI側で実行されます。

## 初回以外で気になる箇所

- `loadWaveformPayload()` は波形の取得前後でANLZ全体のハッシュを確認し、
  さらに前後で `refresh()` によるPDB全体の検証を行います。
- デッキへの曲ロードでは、`createTemporaryTrack()` が複数の波形形式を取得するため、
  同じ解析ファイル・PDBの検証が繰り返される構造です。
- ブラウザの波形キャッシュは行モデルの `setRows()` でクリアされます。
  プレイリスト切り替え後に、再度波形取得が必要になる場合があります。
- 現在の版には、以前のLinux調査で記録した毎秒の再生履歴検索と、
  USB保存中のmutex待ちも残っています。ただし今回報告された「初回だけ遅い」症状の
  第一候補にはしません。

## 改善する場合の順序

1. **時間と読み取り量を記録する。**
   探索、PDB解析、パス確認、ANLZ処理、GUIへの公開を分け、経過時間・曲数・処理済み件数を記録する。
   GUIの応答確認も加え、待ち表示と実際のGUI停止を区別する。
2. **PDBの曲名・アーティスト・プレイリストを先に公開する。**
   ANLZの読み取りは選択・表示・ロードする曲へ優先的に行い、残りを必要に応じて処理する。
   未準備のキュー・グリッドを誤って利用しない状態管理が必要。
3. **読み込み中も戻る・キャンセルでき、進捗が分かる画面にする。**
   実行中のI/Oと世代管理を対応させ、USB取り外し後の結果を公開しないようにする。
4. **重複する検証をまとめる。**
   同一ファイルの複数波形をまとめて扱うなど、媒体の交換・改変検出を維持したまま読み取りを減らす。

調査時の提案は、計測と進捗の記録、続いてカタログの段階公開でした。
安全確認を単純に削除する高速化は行わず、セッション・媒体の検証を保った設計にします。
その後、ユーザーの希望に沿って0049で曲ロード時の解析へ変更しました。
詳細な処理別ログと、読み込み中の進捗・キャンセル画面は引き続き未実装です。
