# NauticMixxx ryumu版 — 追加・変更内容

更新日: 2026-10-15

Raspberry Pi 5と10インチ・1920×1200タッチパネルでの利用に向けて、
今回の開発で変更したNauticMixxxを **ryumu版** と呼びます。
本書は、開発環境の準備からタップ操作の追加までの変更記録です。

ベースはNauticMixxx 2.0.0 / Mixxx 2.5.6です。
既存の0001〜0044パッチに、今回の0045〜0049パッチと周辺スクリプト・スキンの変更を
加えています。`VERSION` は引き続き `2.0.0` です。
ここでの「ryumu版」は開発版の呼称で、アプリ名・実行ファイル名はNauticMixxxのままです。
既存版全体の履歴は [CHANGELOG](../CHANGELOG.md) と
[パッチ一覧](../patches/README.md) を参照してください。

## Raspberry Pi 5向けの開発準備

- [セットアップスクリプト](../scripts/setup-raspberry-pi-dev.sh) を追加しました。
  Raspberry Pi 5、Debian / Raspberry Pi OS 12 Bookworm・13 Trixie、64bit環境を

- [環境確認スクリプト](../scripts/check-raspberry-pi-dev.py) と

## Linux USB検出と交換判定の改善（0045）

対象: [0045パッチ](../patches/0045-linux-usb-mount-discovery-and-identity.patch)

- 従来の `/media` などに加え、Linuxが報告する実マウントルートを探索対象にしました。
  `/mnt/djusb` のような固定マウント先でも、rekordboxエクスポートを発見できる構成です。
- 候補の重複を除外し、マウント外へ出るエクスポートのシンボリックリンクを拒否します。
- Linuxのストレージ識別にカーネルのマウントIDとブロックデバイスの `diskseq` を追加しました。
  新しいカーネルでは再利用されない一意のマウントIDを優先し、古いカーネル向けの経路も用意しました。
- マウント先が同じでも識別情報が変われば、古いUSBセッションを無効化して再探索します。
- 識別に使うファイルディスクリプタは短期間で閉じ、通常のアンマウントを妨げないようにしました。
- 探索、交換判定、識別情報の解析、ディスクリプタ解放などを確認する10件のテストを追加しました。

PC上の検証に加え、Pi上での物理USB交換・安全な取り外しの確認が必要です。
古いカーネル上の特殊なFUSE・仮想マウントについても追加確認が残っています。

## PC用Linuxビルドの修正

開発PCでのビルド停止を調査し、次を0045に含めました。

- `QT_USE_QSTRINGBUILDER` 有効時の条件式の型不一致を、表示文字列を `QString` として確定させて修正。
- PCH無効時にもビルドできるよう、波形ビューアへ `ControlObject` の直接includeを追加。
- `Q_OBJECT` を持たない独自ウィジェットのテストを、Qt基底型での検索と `dynamic_cast` に変更。
  Qt 6.12の静的検査に対応しました。
- デッキ表示テストの空白行の数え方を修正し、文字端の画素を余分に数えないようにしました。

また、Linuxのブランド生成処理は、内容が同じファイルを書き直さないようにしました。
繰り返しビルド時の不要なヘッダー・リソースの再コンパイルを減らします。

## QUANTIZEのクリック・タップ操作（0046）

対象: [0046パッチ](../patches/0046-rx3-quantize-click-and-touch-toggle.patch)、
スキンの `deck.xml` / `style.qss`

- 各デッキの **QUANTIZE見出し** と **拍数の表示** を押すと、そのデッキのON・OFFを切り替えます。
- 設定済みの拍数は保持します。
- OFFでも文字をグレーで表示し、押せる場所が分かるようにしました。ONは既存のアクセント色です。
- コントローラーからの変更も両方の表示へ反映します。
- 透明なネイティブボタンを表示に重ね、表示領域のリサイズにも追従します。
  指を離した時に1回切り替わり、領域外で離した場合はキャンセルします。
- 左右デッキの独立性、外部変更、キャンセル、タップを確認する4件のテストを追加しました。

## TEMPO RANGEのクリック・タップ操作（0047）

対象: [0047パッチ](../patches/0047-rx3-tap-tempo-range.patch)

- 各デッキの範囲表示を押すと、**6% → 10% → 16% → WIDE → 6%** の順に切り替えます。
- プリセット以外の範囲では、現在値より大きい次のプリセットへ進みます。
- コントローラーなどで変更した現在値を使い、表示と色も更新します。
- 範囲の切り替え時に現在の再生速度を保持します。実際のエンジンを使ったテストでも確認しました。
- 領域外でのリリースはキャンセルします。
- デッキの独立性、外部変更、タップ、キャンセル、再生速度の保持を確認する4件のテストを追加しました。

## ブラウザのタッチ操作追加（0048）

対象: [0048パッチ](../patches/0048-rx3-browser-touch-load-and-navigation.patch)、
スキンの `topbar.xml` / `style.qss`

| ボタン | 配置 | 動作 |
| --- | --- | --- |
| BROWSE | 演奏画面の上部 | ブラウザを開く |
| LOAD 1 | ブラウザ上部 | 選択した曲をデッキ1へロード |
| LOAD 2 | ブラウザ上部 | 選択した曲をデッキ2へロード |
| PERFORMANCE | ブラウザ上部 | 演奏画面へ戻る |

- LOADは物理コントローラーと同じデッキ指定のロード制御を使います。
  ロード操作自体は再生開始を指示しません。
- 曲が未選択の場合や、対象デッキが既存のLoad Lock設定で保護されている場合は無効表示になります。
  押した瞬間にも条件を再確認します。
- 再生中のロード可否は既存設定に従います。
- PERFORMANCEで戻ってもブラウザの選択・スクロール状態を保持し、BROWSEで再び開けます。
  画面移動だけでは曲のロードや再生状態を変更しません。
- 未選択、ロード先指定、再生中の保護、タップ、画面往復、1280幅・1920幅の配置を確認する
  6件のテストを追加しました。

曲一覧のタップ選択、タッチスクロール、検索キーボード、プレビューなどは既存機能です。
今回の追加は、画面上でロード先を指定し、演奏画面とブラウザを往復できる操作です。

## USB一覧の波形をバックグラウンドで読み込む（0056）

対象: [0056パッチ](../patches/0056-browser-background-waveform-previews.patch)

- PDBから曲名・アーティスト・プレイリストを先に表示し、一覧の曲の解析ファイルを順次バックグラウンドで読み込みます。
- 表示中の行の波形を優先して読み込み、準備できた行から更新します。デッキへ曲をロードする操作は不要です。
- 同じUSB接続中は解析結果を再利用します。画面外の曲は解析情報を先読みし、波形デコードは表示時に行います。
- 一覧切り替えで残りの待機処理を取り消し、古い一覧や取り外したUSBの結果は表示しません。
- 波形がない曲や壊れた解析ファイルは空欄のままにし、後続の曲を処理します。

## USBの解析ファイルを曲ロード時に読み込む（0049・当時の動作）

対象: [0049パッチ](../patches/0049-rekordbox-load-analysis-on-track-demand.patch)

- 初回はPDBから曲名・アーティスト・プレイリストを作成し、全曲のANLZを読み終える待ちをなくしました。
- キュー・グリッド・波形の解析は、デッキやヘッドホンプレビューへ曲をロードする時に、その曲だけ行います。
- 解析済みの情報は同じUSB接続セッション内で再利用します。曲一覧・プレイリストの切り替えや
  スクロールだけでは解析ファイルを開きません。
- ブラウザの小さな波形プレビューは、未ロード曲では空欄です。一度ロードした曲では表示できます。
- カバー画像は別経路です。USBに画像があれば、曲のロード前でもINFO画面で表示できます。
- USB交換、PDBの改変、解析ファイルの所有者・パス・波形内容の検証、保存時の確認は維持しました。
- 1000曲のテスト用USB構造で、一覧・プレイリストが解析前に利用でき、
  行選択後のGUI更新でも解析を始めず、1曲のロードでその曲だけ解析されることを確認しました。
  新規4件のテストに加え、既存のキュー・グリッド・波形・保存テストも実行しました。
- Windows版1.5での報告と調査の詳細は [USB読み込み速度の調査](USB-LOAD-PERFORMANCE-JA.md) に記録しています。
  実際のWindows PC・USBでの時間短縮は未計測です。

## ビルド・パッケージ・検証の整備

- Linuxビルドに `RX3_BUILD_TYPE` を追加しました。
  `Release`、`RelWithDebInfo`、`Debug` を指定でき、既定は `Release` です。
- `compile_commands.json` の生成を有効にし、エディタでのC++解析に使えるようにしました。
- Linuxのテスト指定を `Rekordbox*` と `TrackCapabilityPolicyTest.*` まで拡張しました。
  既存の起動・更新チェック・RX3関連テストも引き続き対象です。
- テストへスキンのディレクトリとスタイルシートの場所を渡すようにしました。
- Linuxパッケージのメタデータに記録するパッチ数を、ファイルからの自動集計へ変更しました。
- Windowsのビルド・配布処理とリリース監査のパッチ数チェックを49に更新しました。
  Windowsの `near` / `far` 識別子チェックは維持しています。

## 保留・未対応

- **USB初回読み込みの実機計測**：0049で曲ロード時の解析に変更しましたが、
  対象のWindows PC・USBでの所要時間とGUI応答の確認はまだ必要です。
  PDB解析中の進捗表示・キャンセル画面、重複するPDB検証の削減も未実装です。
- **低優先度のバックグラウンド先読みは検討段階**：一覧を先に使えるようにした後、
  表示中・選択中の曲から1曲ずつ先読みする案です。手動ロードの優先、メモリ上限、
  USB取り外し時の中止が必要です。現時点では全曲のバックグラウンド先読みは実装していません。
- **小さいパッドの拡大は保留**：HOT CUE / GATE CUE、BEAT LOOP / SLIP LOOP、
  BEAT JUMP、RELEASE FXなどのサイズは今回変更していません。
- USB書き戻し中にGUIが同じmutexを待つ問題と、毎秒の再生履歴の全曲検索は未対応です。
  詳細は [コード調査](PI-LINUX-CODE-AUDIT-JA.md) に記録しています。
- Piでの全体ビルド、GPU描画負荷、音声出力・遅延・音切れ、物理USB交換、
  Waylandでの動作、実パネルのタッチ座標・同時操作は実機確認が必要です。
